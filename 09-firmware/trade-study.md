# 09 — Прошивка и алгоритмы

## Постановка вопроса

Слияние потоков данных с 6+ сенсоров, оценка достоверности по расхождению
двух PM-каналов, температурно-влажностная компенсация, OTA-обновления,
интеграция с Meshtastic и конфигурация через Wi-Fi/BLE.

## Критерии выбора

1. Минимальный кратный каркас: esp-idf vs Arduino/PlatformIO vs ESPHome-модуль.
2. Слияние данных: сначала простые пороги (v1), ML-калибровка (v2, OTA).
3. OTA-архитектура (двойной раздел, подпись прошивки).
4. Интеграция Meshtastic: форк их firmware vs отдельное приложение-узел.

## Стек (черновик)

| Слой | Выбор | Комментарий |
|---|---|---|
| Ядро | ESP-IDF (v5.x) | двухъядерное расщепление: ядро 0 — сенсоры/ALS, ядро 1 — сеть |
| Драйверы | ESP-IDF + кастомные | SDS011/PMSA003 UART-парсеры, MOX-ADC, AFE I²C |
| Сеть | lwIP + esp_eth (Ethernet) + esp_wifi | приоритет Ethernet, Wi-Fi — fallback/config |
| Mesh | Meshtastic firmware как библиотека/форк | открытый вопрос (см. 06) |
| ML | TFLite Micro / чистый C (AdaBoost) | AdaBoost: R² 0.171→0.784 по литературе (из ТЗ) |
| OTA | esp_https_ota + подпись | двойной раздел A/B |
| Конфиг | BLE-приложение Meshtastic + web-UI | Wi-Fi AP при первом запуске |

## Алгоритмы

### v1 (поставка на Kickstarter): простая двойная верификация

```
Δ = PM2.5_SDS011 − PM2.5_PMSA003
если |Δ| < 0.15 × mean(PM_A, PM_B) → confidence = HIGH
иначе → confidence = LOW (флаг в телеметрии, данные помечены)
выход = медиана(PM_A, PM_B)  # по 30-секундным скользящим средним
```

- Частота опроса: SDS011 1 Гц → 30 с скользящее среднее; PMSA003 аналогично;
  MOX — 60 с; O₃ (SPEC) — 30 с; SHT4x — 10 с.
- Компенсация RH: если RH>40% → понижение confidence + флаг;
  T-компенсация MOX по полиномам из datasheet.

### v2 (OTA после запуска): AdaBoost-регрессия

- Признаки: PM_A, PM_B, Δ, RH, T, (опц.) время суток/сезон.
- Модель обучается на привязке к референс-станциям (данные краудсорсинга после деплоя).
- Деплой: float32-модель, TFLite Micro или hand-rolled деревья (<50 КБ RAM).

### Компенсация O₃/NO₂

- SPEC 110-406: кросс-чувствительность NO₂ 1:1 → O₃_истинный = O₃_изм − NO₂_канал
  (с коэффициентами из datasheet и от калибровки).

## Требования к надёжности

- Watchdog: контроль потока данных сенсорных UART (потеря потока → рестарт сенсора, не MCU).
- Логика «деградация»: отказ одного PM-канала → продолжение работы на другом с флагом.
- Локальный буфер: 7 суток данных (RAM+PSRAM+flash) при потере сети.

2. Хранение/выгрузка истории: где (домашний сервер/MQTT? MeshADV-совместимость?)
