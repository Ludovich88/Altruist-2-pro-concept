# 01 — Ядро системы (MCU)

## Постановка вопроса

Требование изменилось в ходе проработки концепта: изначально ТЗ писалось под
ESP32-S3, затем добавилось требование **полноценного проводного Ethernet + PoE**
(F5 в ТЗ). У ESP32-S3 нет (R)MII-интерфейса → для него Ethernet возможен только
через внешний SPI-контроллер (W5500/DM9051), реально дающий ~8–15 Мбит/с — это
компромисс, а не полноценный Ethernet. **Вариант S3+W5500 и классический ESP32
исключены из рассмотрения** (2026-10-07) как нежизнеспособные при текущих
требованиях: SPI-Ethernet не тянет F5, а LX6 без SIMD не закрывает edge-AI.

Осталось **три варианта** — по каждому отдельный файл с подробным разбором
(сильные/слабые стороны, риски, проблемы):

- [esp32-p4-esp32-c6.md](esp32-p4-esp32-c6.md) — двухчиповая связка P4 + C6
- [esp32-p4-esp32-c5.md](esp32-p4-esp32-c5.md) — двухчиповая связка P4 + C5 (dual-band)
- [esp32-s31.md](esp32-s31.md) — одночиповое решение «всё в одном»

## Критерии выбора

1. Аппаратный Ethernet MAC (RMII/RGMII).
2. Радио: Wi-Fi/BLE на кристалле или через сопроцессор.
3. Вычислительный запас: слияние данных 4 сенсоров + edge-AI калибровка (AdaBoost).
4. Зрелость: ESP-IDF-поддержка, референсные дизайны, сообщество.
5. Стоимость чипа + обвязки, доступность у дистрибьюторов.
6. Бюджет мощности — не критично: PoE даёт до 12.95 Вт (Class 0).

> Примечание: ESP-Hosted (сопроцессор Wi-Fi по SDIO) — отработанный, но двухчиповый
> путь: две прошивки, аккуратная разводка SDIO, +$2–3 BOM.

### Вариант B: ESP32-P4 + ESP32-C6

**Суть:** P4 — приложение и EMAC RMII (PHY IP101G/LAN8720), C6 — Wi-Fi/BLE-модем
по SDIO (esp_wifi_remote/ESP-Hosted).

**Сильные:** максимальная мощность (400 МГц dual-core); связка проверена вендором
и индустрией; готовый референс с PoE (Waveshare ESP32-P4-WIFI6-POE-ETH); C6 зрелый
и дешёвый (LCSC $1.69@1k); SAR ADC 14 кан. на P4.

**Слабые:** две прошивки; SDIO-мост; datasheet P4 PRELIM v0.7; Arduino не
поддерживается; Wi-Fi только 2.4 ГГц.

**Вывод:** безопасный, проверенный и гибкий выбор. Детали: [esp32-p4-esp32-c6.md](esp32-p4-esp32-c6.md).

### Вариант B': ESP32-P4 + ESP32-C5

**Суть:** та же топология, радио C5 — единственный dual-band Wi-Fi 6 (2.4+5 ГГц).

**Сильные:** 5 ГГц — чистый эфир в плотной застройке; вся мощь P4; готовая
core-плата WT01P4C5-S1.

**Слабые:** все двухчиповые слабости B + **дефицит C5-модулей** (LCSC/DigiKey/Mouser —
нет в стоке, lead time до 20 нед, сток только у ASIA-посредников с наценкой);
экосистема C5 моложе; двойная новизна (мост + новое радио).

**Вывод:** технологически привлекателен, supply-риск сейчас неприемлем для
Kickstarter-таймлайна; разумно как опция «C5-совместимая посадка модема» поверх B.
Детали: [esp32-p4-esp32-c5.md](esp32-p4-esp32-c5.md).

### Вариант C: ESP32-S31

**Суть:** один чип: GMAC 1G (RMII/RGMII) + Wi-Fi 6 + BT 5.4 (+Classic) + 802.15.4.

**Сильные:** один чип/одна прошивка/один OTA-контур — самая простая модель
сопровождения; SIMD + 320 МГц под edge-AI; массовое производство с 27.07.2026;
60 GPIO, 8 ADC-каналов, USB HS, TWAI.

**Слабые:** самая молодая экосистема; требует ESP-IDF 6.1+; Arduino закрыт до
arduino-esp32 4.0 (~11/2026) — блокер Meshtastic-порта (issue #10981); наличие
модулей у западных дистрибьюторов не подтверждено; Wi-Fi без 5 ГГц.

**Вывод:** архитектурно чистое решение «всё в одном»; основной риск — зрелость.
Детали: [esp32-s31.md](esp32-s31.md).

## Черновая рекомендация

**Развилка для решения:**

1. Если главнее **зрелость и проверенность** → **B: P4 + C6**
   (готовые модули/платы, PoE-референс есть; посадку модема сделать C5-совместимой
   как страховку).
2. Если к моменту фиксации (ADR-002) закрыты **IDF 6.1 + Arduino 4.0 + Meshtastic
   #10981 + модули у дистрибьюторов** → **C: ESP32-S31** становится фаворитом
   (одночиповая простота на весь жизненный цикл).
3. **B' (P4 + C5)** — не самостоятельный выбор до стабилизации поставок C5;
   использовать только как запасную посадку радио в варианте B.

Перед фиксацией решения проверить: наличие S31-модулей у дистрибьюторов
(Mouser/DigiKey/LCSC), статус Meshtastic #10981 (S31) и C5-стоки, релиз
arduino-esp32 4.0.

## Исключённые варианты (архив)

- **ESP32-S3 + W5500 (SPI Ethernet)** — исключён 2026-10-07: SPI-Ethernet ~8–15 Мбит/с
  не соответствует требованию F5 «полноценный Ethernet»; свой TCP-стек W5500 вне
  lwIP; +1 чип и шина SPI с арбитражем против LoRa. Был бы приемлем только при
  смягчении F5 до «10 Мбит/с достаточно».
- **Классический ESP32 (+PHY)** — исключён 2026-10-07: LX6 без SIMD/векторов —
  edge-AI калибровка под вопросом; только Wi-Fi 4; мало RAM под слияние 4 сенсоров.
  RMII-путь и PoE-референсы (M5Stack PoESP32) сохранены в истории обсуждения.

*Цены/наличие проверены поиском 2026-10-06/07; перед закупкой перепроверить у дистрибьюторов.*
